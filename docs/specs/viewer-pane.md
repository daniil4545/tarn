# Spec: viewer pane

Status: built in `tarn-v1.0.0`. Canon for the keys, tabs, files tree, editor and disk-change behavior of the viewer pane. The parent spec is `docs/spec.md` (requirements R5, R6, R9); the module is `docs/modules/viewer.md`; placement of several viewers is `docs/modules/layout.md`.

1. Purpose: read and edit a file next to a session without another app.
2. Input: a path from a click (`path`, `path:line`), `tarn open` or the files tree. Output: the file, rendered or as source.
3. How it works: the first open puts a pane to the right of the terminal area of a window tab; more viewers and their placement are in `docs/modules/layout.md`. Tabs: a file opens as a preview tab (italic) that the next open replaces; a double click, an edit or a drag pins it. The files tree sits on the right of the pane, rooted at the terminal's cwd; the Files button toggles it inside the pane and Esc hides it. Cmd+B is the one pane key, from the terminal and from the pane; the Toggle File Viewer button in the sidebar header (and in the rail) does the same. It opens and hides, it never closes: with no pane it opens the pane with the tree only (rooted at the terminal's cwd, no file open) and puts the keyboard in the tree; a hidden pane comes back as it was hidden, with the keyboard in it; a shown pane, with files or not, hides whole (tabs, unsaved edits and tree state are kept; closing a window still asks about the edits) and the keyboard goes to the terminal. Cmd+W with the keyboard in the pane closes the pane when no file is open, otherwise the active tab; the last tab closes the pane. The Files button and Esc toggle the tree inside a pane with files; in a pane with no file they hide the pane. Enter on a file in the tree opens it and moves the keyboard into it. The viewer is optional: a Settings switch, on by default, turns off new panes. Arrows: Left in the tree (not on an open folder) goes to the file, Right in a viewed file goes to the tree. A path click shows a hidden pane and focuses it; `tarn open` leaves it hidden and never moves the keyboard. Markdown shows rendered (highlight, mermaid with a per-diagram Source toggle, Copy on code blocks, task checkboxes written back to the file) or as source in an editor (Cmd+E); Cmd+S saves, an edit marks the tab dirty. Cmd+= (also Cmd++), Cmd+- and Cmd+0 zoom the pane while it holds the keyboard; the last two and Cmd++ follow the terminal's font size keys, in Safari's steps from 50% to 300%; one zoom for every pane, kept across launches. Ghostty's tab and window keybinds that have no menu item (Cmd+1 to Cmd+9, previous and next tab, move tab, previous and next window, tab overview, maximize, decorations, background opacity; the user's own keys for them too) work while the pane holds the keyboard: the pane runs them on the focused terminal of its tab. Terminal input keys (Cmd+Left, Cmd+Backspace and the like) stay with the page. Other text files show highlighted with line numbers and edit the same way; `path:line` scrolls to the line and marks it. Markdown is rendered from vendored assets in a WKWebView. A file changed on disk is re-rendered with the scroll kept; with unsaved edits the pane shows "The agent changed this file and you have unsaved edits" with "Take the agent version" and "Keep mine".
4. Rules: no network: a `WKContentRuleList` blocks everything except `tarn-md://`, which serves bundled assets and local images of allowed folders; raw HTML inside markdown is escaped; `http(s)` links open in the system browser. Files over 5 MB or not UTF-8 get a one-line notice. The theme follows the terminal background. `tarn open` needs an absolute path, answers ok or an error and opens text files only; non-text files open in their default app. Ghostty's undo reopens a closed pane.
