# Demo module contracts

What every module may rely on. Module description: `docs/modules/demo.md`. Checks: `demo/test/check_0.py`.

## State

`state.js`: `register(part, initial)` returns the only setter of `part`; a second `register` throws. `read(part)` and `snapshot()` return frozen data. Every setter call emits `state:changed {part}`.

| Part | Writer | Shape |
|---|---|---|
| `workspaces` | `workspace.js` | `{tabs: {id: {id, title, cwd, layout}}, wss: [{id, name, tabs}], cur}`, seed in `seed.js` |
| `registry` | `registry.js` | `{paneId: {state, since, seen, failed, request, sawPermissionRequest, permissionAgent, answerable}}` |
| `config` | `config.js` | `{key: value}` for every key of `OPTIONS` |
| `vfs` | `vfs.js` | snapshot of the in-memory disk |

Write a new part only through `register`. A tab's `layout` is a tree owned by `workspace.js`; the seed has one leaf `{pane: "pN"}` per tab.

## Bus

`bus.js`. `bus.on(event, fn)` returns an off function. `bus.emit(event, detail)`. `bus.handle(name, fn)` sets the single handler of a command (a second one throws). `bus.cmd(name, payload)` runs it. A throwing or unknown command is caught: `console.warn`, an entry in `errors`, a `toast` event; `cmd` returns undefined.

Commands and their writers (the main ones; `rg "bus.handle\(" demo/js` lists all):

| Command | Payload | Writer |
| --- | --- | --- |
| `tab.new`, `tab.close`, `tab.go`, `tab.move` | `{ws?, id?, n?, to?, header?, after?}`; `ws: "loose"` in `tab.move` ungroups, below group `after` or at the tail | `workspace.js` |
| `pane.split`, `pane.close`, `pane.focus`, `pane.zoom`, `pane.resize`, `pane.equalize`, `pane.undo` | `{id?, dir}` | `workspace.js` |
| `ws.new`, `ws.rename`, `ws.delete` | `{id?, name, folder?, closeTabs?}`; ungrouped tabs are headerless `loose` blocks anywhere in `wss`; two never touch | `workspace.js` |
| `hook` | `{pane, name, event}` | `registry.js` |
| `card.answer` | `{pane, allow}` | `term-pane.js` (the pane's shell answers; the script then emits `hook`) |
| `viewer.open` | `{path, line?, pane?}` | `viewer.js` |
| `config.set`, `config.reset` | `{key, value}` | `config.js` |
| `vfs.write` | `{path, text, by}` | `vfs.js` |

Events: `state:changed {part}`, `config:changed {key, value}` (not sent for the values loaded at start: read `read("config")` once at init), `vfs:changed {path, by}`, `pane:output {id}`, `toast {text}`, `pane:focused {pane}` (the pane module emits it on focus; the registry marks the session seen), `pane:disposed {pane}` (emitted when a pane is freed after the undo window; the registry drops its record), `chrome:changed {colors}` (`settings-effects.js`: the window colors changed; `colors` is the derived set or null for a forced light or dark window).

## Registry

`hook {pane, name, event}`: `name` is a Claude Code hook name, `event` carries `agent_id`, `background_tasks`, `notification_type`, `reason`, `request`, `answerable` as in `SessionRegistry.swift`. Only the registry writes `registry`. `handle(session, name, event)` is the pure transition table (spec section 8). On a state change the registry sets `since` and `seen` (`seen` = the pane is focused now).

Labels follow the canon: `waiting` and not `seen` is shown as "done, not seen"; there is no state `done`.

## Theme and window colors

`theme` is the name of a Ghostty theme file (`Catppuccin Mocha`) or empty for Ghostty's built-in default; the 771 names and palettes are in `themes-data.js` (generated by `demo/tools/gen-themes.py`), `themeFor(name)` in `themes.js` returns the engine theme. An unknown name gives the default.

`window-theme` `auto` and `ghostty` take the window colors from the terminal theme: `chrome-theme.js` `deriveChrome(theme)` returns `bg`, `fg`, `chrome`, `menu`, `line`, `div`, `muted`, `key`, `code`, `accent` (rule at the top of that file), `settings-effects.js` writes them as custom properties on the root (`PAGE_VARS`) and sets `data-theme` from the background lightness. The viewer iframe gets the same colors as `--p-*` (`VIEWER_VARS`, `viewer.js`). `system`, `light` and `dark` remove the custom properties and use the built-in palettes. The default theme is dark whatever the system is.

## Drop marks

`dnd.js` draws one `.drop` element in `#ws`: a 3 px bar in the system accent (`--sys-accent`) at the cut between the dragged window and what stays (the middle of the target for a half, the top edge of the content for a drop into a viewer's tabs). A refused drop has no bar: the element holds a gray chip with the reason. In the sidebar a tab row drags with pointer events, not HTML5 drag (browsers lose the drop or cancel the drag when the list moves under it): after a 4 px move the row gets `lifted` (hidden), a solid copy (`dragghost`) follows the pointer, and the element below the landing place takes the row's slot as a top margin that slides open in 150 ms: before a row in its upper half, after it in its lower half, at the end of a workspace over its header. Esc or a release outside the sidebar leaves the tab where it was. A workspace move is HTML5 drag and draws `wsline`, a 3 px line in the system accent where it lands.

## Config

`OPTIONS` lists every key with `type`, `def` and bounds or `values`, named as the Ghostty keys, plus `tab-style`. `config.set {key, value}` validates, stores, persists (`tarn-demo-v1:config`) and emits `config:changed`. Invalid values throw, so the bus reports them. `config.reset` restores defaults.

## Keys

Rows are data in `keys/*.js`: `{id, chords, alt, when, group, text, cmd, payload}`; chords like `Cmd+Shift+D`, fallbacks `Ctrl+Alt+<key>`. A slice exports its rows; `main.js` concatenates all rows and calls `installKeys(rows, {focus})`, where `focus()` returns `terminal`, `viewer`, `any` or `modal` (a settings window is open). `installKeys` throws if `checkRows` finds a duplicate chord in an overlapping `when`, a chord that is shell input (Ctrl+letter, Alt+letter alone), or a fallback that is not Ctrl+Alt+key. Match is by the Latin letter of `e.key`, else by `e.code`; the handler runs in the capture phase and stops the event.

## Pane

`createPane(id, {cwd})` returns `{id, el, term, focus(), screenText(), dispose()}`. `createPane` lives in `term-pane.js`. `dispose()` removes the element and emits `pane:disposed`.

## Terminal adapter

`term-adapter.js`: `await createTerm(parentEl, options)` returns a `Term`. Only this file imports the engine.

| Member | Meaning |
|---|---|
| `cols`, `rows`, `options` (frozen copy), `lineCount`, `topRow`, `cursorRow` | geometry; rows are absolute: scrollback first, then the screen |
| `write(data)`, `paste(text)`, `focus()`, `fit()`, `dispose()` | |
| `onData(fn)`, `onResize(fn)`, `onSelection(fn)` | each returns an off function; `onSelection` fires after a mouse selection ends |
| `setOption(key, value)` | `theme`, `fontSize`, `fontFamily`, `cursorStyle`, `cursorBlink` |
| `optionAsAlt`, `copyOnSelect` | setters; Alt+key sends ESC + key when on; selection copies to the clipboard when on |
| `lineText(row)`, `screenText()` | text with blanks kept |
| `addLinkProvider(find, activate)` | `find(lineText)` returns `[{start, end, text}]` (columns, end exclusive) |
| `scrollToRow(row)`, `getSelection()`, `clearSelection()`, `select(col, row, length)` | |
| `cellCentre(col, row)` | page position of a visible cell, for tests |

The shell keeps its own prompt rows (engine has no OSC 133 marks): store `cursorRow` when a prompt is written, jump with `scrollToRow`. Pass `fontFamily` as a CSS list; `createTerm` waits for that font before it measures cells. The engine fixes the palette in the terminal when it opens, so `setOption("theme")` maps the old palette, text and background colors to the new theme while drawing and redraws (truecolor text keeps its color). Do not call `t.select`/clicks in tests faster than a double-click interval after a click (the engine counts them as a double click).

## Time

`clock.js`: `now()`, `after(ms, fn)`, `cancel(id)`. All scripts and timeouts of the demo use it. A test calls `__tarn.clock.freeze()` first, then `advance(ms)`.

## Test surface

`window.__tarn` (read only): `snapshot()`, `screen(id)`, `linkAt(id, text)`, `term(id)`, `viewer().state()`, `clock.freeze()`/`advance(ms)`, `errors`, `requests()`. The pane and viewer modules set `hooks.screen`, `hooks.linkAt`, `hooks.term`, `hooks.viewer` from `test-contract.js`; an unset hook throws "test hook not set".

## Persistence

`storage.js`: `load(part, seed)`, `save(part, value)`, `clearAll()`; key `tarn-demo-v1:<part>`; bad JSON gives the seed and a `toast`; a missing or blocked storage is tolerated.

Survives reload: config, workspaces/tabs/layout (if `window-save-state` allows), vfs edits, shell history (last 200). After "Reset demo": config to defaults, workspaces and vfs to the seed (ids `t1`, `w1`), history cleared. Never survives: scrollback, a running `claude`, the undo stack; a reload in the middle of `claude` starts the pane at a fresh prompt.

## Viewer bundle in an iframe

The app bundle `macos/Sources/Features/Tarn/Viewer/tarn-viewer.{html,js,css}` runs in an iframe on a static server after two changes: the meta CSP is rewritten (`script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:`) and `window.webkit.messageHandlers.tarn.postMessage` is defined by an external script loaded before `tarn-viewer.js` (an inline script is blocked by the CSP). The page then answers `tarn.setChrome(...)` and `tarn.setDoc(...)` calls (shapes: `ViewerModel.swift` `pushChrome`, `pushDocument`) and posts `{t: "ready"}`, `{t: "tab", ...}` and the other messages. Unmodified, the CSP blocks the script and style, and `window.tarn` is undefined. Images use `tarn-md://file/<abs path>` and need the same rewrite.
